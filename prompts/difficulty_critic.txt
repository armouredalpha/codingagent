DIFFICULTY DEFINITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

EASY — 5–10 min. Zero lines of new code written.
  The student's entire job is one of:
    (a) Find and change ONE wrong string in otherwise-complete code:
        wrong topic name (/scan_data → /scan), wrong frame ID (world → base_link),
        wrong service name, wrong field name — exactly one string to fix.
    (b) Run a `ros2` CLI command to observe or reconfigure the system.
        (ros2 topic echo, ros2 param set, ros2 run, opening RViz2 and adding correct display)
  Signals of EASY:
    - Starter code is functionally complete except for one wrong string literal
    - No TODO blocks. Bug is marked with `# BUG: fix this value`
    - Reference solution differs from starter in exactly ONE string value
    - Bloom: apply (recognise the correct ROS2 name/convention)

MEDIUM — 10–20 min. Student fixes 1–2 values or field names, writes no new logic.
  The student must find and correct 1–2 wrong values or field expressions:
    wrong field:  msg.linear_vel → msg.linear.x
    swapped axis: msg.angular.x → msg.angular.z
    wrong speed:  self.speed = 0.0 → self.speed = 0.5
    wrong rate:   timer_period = 0.1 → timer_period = 0.5
    wrong topic:  /odom_data → /odom (when 2 places need fixing)
  Signals of MEDIUM:
    - Code is mostly working but wrong in 1–2 specific value/expression places
    - Lines marked with `# BUG: fix this` show where edits are needed
    - No large implementation blocks — just targeted value corrections
    - Bloom: apply-to-analyze (student must know which field/value is correct)

HARD — 15–25 min. Student writes 1–2 missing critical lines of code.
  The student must supply lines that are entirely absent:
    missing publisher init: self.pub = self.create_publisher(Twist, '/cmd_vel', 10)
    missing callback line:  distance = math.sqrt(dx**2 + dy**2)
    missing transform:      t = self.tf_buffer.lookup_transform('map', 'base_link', rclpy.time.Time())
  Signals of HARD:
    - Starter has `# TODO: <one-line instruction>` + `pass` where the line should be
    - Exactly 1–2 TODO items, everything else is complete and correct
    - Understanding WHY that line is needed requires domain knowledge
    - Bloom: analyze (student must know the ROS2 API / formula / design pattern)

KEY PRINCIPLE: DIFFICULTY IS ORTHOGONAL TO QUESTION TYPE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Do NOT use total solution size (lines of reference code) as a difficulty signal.
A TYPE_A question with 200 lines of math library code can be EASY if the student
only fixes one wrong formula. A TYPE_B ROS2 node with 30 lines can be HARD if the
student must write the critical missing publisher line.

Use STUDENT WORKLOAD from the starter code:
  - starter_todo_count: number of # TODO blocks student must fill in
  - starter_bug_marker_count: number of # BUG markers student must fix

SCORING (internal — do not include in output)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Score each question 0–100 internally:

  edit_count          (0–40)  — Based on starter_todo_count + starter_bug_marker_count:
                                 0 TODOs + ≤1 BUG = easy (0–15)
                                 0 TODOs + 2 BUGs = medium (16–30)
                                 1–2 TODOs = hard (31–40)
  knowledge_depth     (0–30)  — How much ROS2 domain knowledge is needed to make the correct fix?
  diagnostic_effort   (0–20)  — How hard is it to locate the bug without the # BUG marker?
  integration_scope   (0–10)  — How many ROS2 concepts must the student hold in mind simultaneously?

Mapping: 0–33 → easy | 34–66 → medium | 67–100 → hard

OVERRIDE RULES (these beat the score):
  - starter_todo_count == 0 AND starter_bug_marker_count == 1 → easy regardless of score
  - starter_todo_count == 0 → cannot be hard (no new code written)
  - starter_todo_count >= 1 → minimum medium (student writes new lines)
  - CLI-only task (ros2 run / ros2 topic / RViz2 panels) → easy regardless of topic complexity
  - NEVER use reference solution LOC as a difficulty signal — it reflects question type, not student work
